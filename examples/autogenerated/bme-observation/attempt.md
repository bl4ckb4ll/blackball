# BME observation interchange witness

## Type sketch before implementation

Values: retrieval coverage (complete, partial, failed), returned record count,
classification count, observation identity, provenance, date precision, place,
money period and basis, evidence stage. A zero count is not an availability state.

The first pure operation maps retrieval coverage and a known/unknown qualifying
count to permission to assert a bounded empty result. The intended full boundary
is `decode bytes -> records or error -> domain checks -> unchanged re-encoding`.
Text, source spans and extension fields must survive; malformed bytes must fail.
Effects are limited to reading fixtures and reporting diagnostics. No acquisition,
credentials, network access or institutional conclusions belong in this witness.

## Source and execution boundary

Read canonical Idriç README, STYLE.md and _/EDRIC.md on 2026-11-13. The latter
documents storage-neutral lower-case `choice ... one_of`; STYLE.md supplies
Number and Unicode arrows. The source attempts only the coverage/count decision,
not an invented filesystem/parser interface.

Preflight on the disposable Linux workspace: `which edric idric grease node`
returned only `/opt/codex/runtimes/codex-primary-runtime/dependencies/node/bin/node`
and exit 1. Neither Idriç entrypoint nor Grease was resolved in this environment.
No compiler build, installation, alternate Idriç backend or generated-C fallback
was attempted. Typecheck and Idriç execution are BLOCKED, not a compiler defect.

The actual attempted check was `/usr/bin/env edric --check
/workspace/scratch/17039cda87c1/blackball/examples/autogenerated/bme-observation/BmeObservation.idric`.
It exited 127: `env: edric: No such file or directory`, before argument or source
processing. Therefore even the CLI check spelling was not qualified locally.
The source's expected four outputs are True, False, False, False; they were not
observed from Idriç.

Fallback execution used Node v24.22.1 on disposable Debian 13 x86_64. The initial
escape-fixture test rejected a missing trailing empty field (BME-SHAPE). Restoring
the actual final TAB fixed the fixture; all 19 finite cases then passed. This is
retained as evidence that empty fields cannot be erased by text trimming. The
validator was not relaxed. Final result: contract-v1/fixture-results.tsv.

Independent review then found an empty-table serialization defect and insufficient
calendar-date validation. The implementation now preserves a header-only file and
rejects impossible dates; a valid leap-day control also passes. Final qualification
contains 22 checks, with no change to the contract's source-truth boundary.

## Narrow fallback

The separately labelled JavaScript witness exercises only the BME contract's
finite, synthetic interchange cases. It is a domain test oracle, not a new
source-acquisition client, shared receipt verifier, production data pipeline or
claim that Idriç executed. Existing ai-ci source-ledger checks (revision
4082d7f45b00cd2ea7c81118447fe22c047ba030) provide row/enum/hash checks but do not
decide these BME relationships. No reusable ai-ci implementation is copied here.

Run results are recorded in the contract directory. This fallback can be removed
when a verified maintained Idriç runtime is available and the same positive and
negative fixtures execute there with lossless UTF-8/file I/O. The first blocker
is runtime availability; no language change has been demonstrated necessary.
